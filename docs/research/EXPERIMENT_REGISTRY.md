# AIMA experiment registry

This registry is the central index of experiments and major analyses. A status
describes the state of the implementation and its evidence bundle; it does not
mean that a model is clinically validated.

## Status definitions

| Status | Meaning |
| --- | --- |
| `COMPLETED_VERIFIED` | The run has a versioned configuration/artifact bundle and saved-model or independent metric verification evidence. |
| `COMPLETED_UNVERIFIED` | A run or pilot produced a report/artifact, but a complete independent reproduction record was not found. |
| `IN_PROGRESS` | Work has started and its current state is recorded, but the planned endpoint is not complete. |
| `PLANNED` | A research question or protocol is recorded, but no implementation run has begun. |
| `BLOCKED` | The work cannot proceed under the current evidence or approved data/mask support. |

`COMPLETED_VERIFIED` means reproducible as a research artifact. All local
classification metrics below are internal development estimates on the same
119 local subjects (19 anemia, 100 non-anemia), with no untouched classifier
holdout. They are not independent or clinical performance.

## Evidence and interpretation rules

1. A registry row is not complete until its configuration, dataset provenance,
   code commit, artifact path, validation result, and limitations are recorded.
2. A result report is authoritative only when its referenced artifact and
   source hashes verify. Conversation summaries are not evidence.
3. Exploratory inner-selected rows and the Exp4 robust18 comparison must remain
   visibly distinct from a primary selected model or an independent test result.
4. A private prediction/checkpoint path may be recorded for traceability, but
   the file itself must remain ignored and must not be committed.
5. If a source artifact is missing, downgrade the status or record the row as
   `COMPLETED_UNVERIFIED`, `IN_PROGRESS`, `PLANNED`, or `BLOCKED`; do not fill
   the gap with a narrative claim.
